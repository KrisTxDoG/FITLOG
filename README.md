# Fitlog 健身紀錄 APP

繁體中文、支援手機尺寸的 React + Spring Boot 個人健身網頁。優先實作器材種類、組間休息、每組重量紀錄。

介面採黑色背景與紫色漸層主視覺；共用配色變數及深色元件樣式位於 `frontend/src/theme.css`，基本排版仍由 `style.css` 管理。

## 已實作

### 課表、進步圖與匯出

- **我的課表**：新增、編輯、刪除課表，保存動作順序、每組公斤數／次數、預計分鐘與備註。也可以從訓練紀錄的「存成課表」圖示開啟範本編輯器，再確認儲存。
- **一鍵開始**：課表的「開始訓練」會建立今天的訓練草稿，重設每組完成勾選。可調整重量再儲存；課表本身不會改變，也不計入訓練統計。
- **動作進步**：查看最近 20 個有紀錄的訓練日，切換每日最高重量、訓練總量、總次數；同日多次紀錄會合併。歷史最高重量與累積訓練日使用全部歷史資料。圖下另有數字表格；自體重量動作可切換次數指標。
- **CSV 匯出**：訓練紀錄頁的「匯出 CSV」下載全部紀錄，每列一組，包含日期、名稱、器材、肌群、重量、次數、總量、完成標記與備註。UTF-8 BOM 支援 Excel 中文；含公式起始字元的文字會加單引號，避免被當公式執行。
- CSV 是明細匯出，不包含課表，也不是可直接還原的資料庫備份；完整備份仍須停止後端後備份 `data` 資料夾。

課表儲存於新增的 `templates`、`template_sets` 表，不修改原有訓練資料。API：`GET/POST /api/templates`、`PUT/DELETE /api/templates/{id}`。新增／更新 JSON 包含 `title`、`duration`、`notes`、`sets`（格式同訓練組數，完成狀態會重設）；課表不接受 `date` 欄位。

### 本次新增

- **自訂器材與動作**：在「器材與動作」點「新增器材／動作」，輸入動作名稱、器材種類（可新增）、肌群及組間休息 5–900 秒。資料保存於 H2 的 `custom_exercises` 表，重量仍統一使用公斤。
- **帶入上次紀錄**：動作卡片的「帶入上次」會建立新的訓練，複製該動作最近一次的所有組數、重量與次數；訓練表單也能選動作並「附加上次全部組數」，不會覆蓋現有組數。同一天多次訓練以建立順序判斷最新。
- **完成一組自動休息**：點每列的勾選按鈕，標記完成並立即開始該動作的休息倒數。內建動作為 90 秒，自訂動作使用新增時的設定。取消完成不會重啟計時；改動重量、次數或動作會清除該列完成狀態。
- 完成狀態會在「儲存訓練」時寫入資料庫；新增或帶入組數時清除完成狀態。仍可手動儲存未勾選組數，以支援事後補登；統計包含整筆已儲存的組數。
- 資料庫啟動時以 `IF NOT EXISTS` 新增資料表與欄位，舊紀錄保留。舊資料未包含完成狀態，顯示為未勾選。

新增 API：`POST /api/exercises`，JSON 範例：

```json
{"name":"史密斯深蹲","muscle":"腿部","equipment":"史密斯機","restSeconds":120}
```

`GET /api/exercises` 現在包含 `restSeconds`；每組資料新增 `completed` 布林欄位，舊呼叫未傳時預設為 `false`。

自訂器材照片、重量單位切換及動作修改／刪除尚未加入。

- **器材與動作庫**：槓鈴、啞鈴、機械器材、滑輪器材、自體重量，共 16 個動作。可搜尋名稱、肌群、器材並篩選器材種類。
- **重量紀錄**：每組分別記錄動作、公斤數、次數；新增組數會沿用上一組。可修改或刪除整筆訓練。
- **休息計時**：30／60／90／120 秒，亦可自訂 5–900 秒。支援暫停、繼續、重設，倒數結束有畫面提示與短音效。訓練表單內也可使用。
- **紀錄查詢**：日期、訓練時間、備註、每組明細，以及各動作歷史最高重量。
- **總覽**：本週訓練次數、分鐘、重量總量及每日分鐘圖。
- **資料保存**：H2 檔案資料庫保存訓練；一般新增表單草稿及計時狀態保存於瀏覽器。
- **驗證與錯誤處理**：禁止未來日期、負重量、零次數、未知動作；儲存失敗保留表單內容。

## 啟動方式 A：Docker

先安裝並啟動 Docker Desktop，在專案根目錄執行：

```sh
docker compose up --build
```

開啟 http://localhost:8088 。資料保存在 `fitlog-data` volume；停止可使用 `docker compose down`。請勿加 `-v`，否則會刪除資料。

## 啟動方式 B：本機開發

需求：Java 17 或 21、Maven 3.6.3 以上、Node.js 22.12 以上。

第一個終端啟動後端：

```sh
cd backend
mvn spring-boot:run
```

第二個終端啟動前端：

```sh
cd frontend
npm ci
npm run dev
```

開啟 http://localhost:5173 。前端將 `/api` 代理到 `127.0.0.1:8080`，不用另設 CORS。

後端預設只監聽 `127.0.0.1`；Docker 內使用容器網路，僅前端 8088 埠綁定本機。

## 正式建置與測試

也可先在 `frontend` 執行 `npm ci`、`npm run build`，再在 `backend` 執行 `mvn package`。後端會把前端 `dist` 一起打包進 JAR，啟動 JAR 後直接開啟 **http://127.0.0.1:8080**，無須另外啟動前端伺服器。

此工作區已完成建置，可在專案根目錄執行 `powershell -File .\start.ps1`。此腳本優先使用已安裝的 Java，也會偵測本次工作區下載的可攜 JDK；搬到其他電腦後需先安裝 Java 17 或 21。按 Ctrl+C 停止。

另附的 `fitlog-app.jar` 是前後端合併版本。安裝 Java 後可執行 `java -jar fitlog-app.jar`，再開啟 http://127.0.0.1:8080 。此方式會在執行目錄建立 `data`，請固定從同一目錄啟動。

```sh
# backend 目錄
mvn test
mvn package
java -jar target/fitlog-1.0.0.jar

# frontend 目錄
npm test
npm run build
npm run preview
```

若 Windows 的受限執行環境阻擋 Vite 讀取父目錄，建置／預覽可使用 `npm run build -- --configLoader native`、`npm run preview -- --configLoader native`，需 Node.js 22.12 以上。

## 操作流程

1. 「器材與動作」選擇器材分類，點動作卡片的 `+`，或從首頁「新增訓練」開始。
2. 填訓練日期、分鐘，每一列代表一組。重量單位為公斤，小數最多兩位。
3. 做完一組後，在表單下方啟動組間休息。新增下一組時可直接沿用上組資料。
4. 訓練完成按「儲存訓練」，即可在訓練紀錄查看、編輯或刪除。
5. 動作卡片顯示所有已儲存組數中的最高重量。

自體重量動作的重量填 `0`；負重引體向上等動作只填額外負重。啞鈴單邊或雙邊重量請自行維持一致的紀錄方式。總量是重量 × 次數，不是卡路里或身體總負荷。

## API

| 方法 | 路徑 | 用途 |
|---|---|---|
| GET | `/api/exercises` | 器材／動作目錄 |
| GET | `/api/workouts` | 所有訓練，日期由新至舊 |
| POST | `/api/workouts` | 新增訓練，回傳 201 |
| PUT | `/api/workouts/{id}` | 取代該筆訓練與全部組數 |
| DELETE | `/api/workouts/{id}` | 刪除訓練及組數，回傳 204 |

新增／編輯範例：

```json
{
  "title": "胸部與三頭訓練",
  "date": "2026-09-16",
  "duration": 45,
  "notes": "最後一組保留餘力",
  "sets": [
    { "exerciseId": "bench", "reps": 10, "weight": 40 },
    { "exerciseId": "bench", "reps": 8, "weight": 45 },
    { "exerciseId": "triceps", "reps": 12, "weight": 15 }
  ]
}
```

`title` 1–80 字、`duration` 1–600 分鐘、`notes` 最多 1000 字、每筆 1–200 組、`reps` 1–1000、`weight` 0–1000 公斤。每組 `exerciseId` 必須來自動作目錄。

修改和刪除不存在的 ID 回傳 404；輸入不合法回傳 400；修改使用資料庫交易，避免儲存一半。

## 保存與範圍

- 本機執行時，資料在後端工作目錄的 `data/fitlog.mv.db`；請先停止後端再備份完整 `data` 資料夾。`DB_URL` 可覆寫資料庫 URL，`DB_PASSWORD` 可覆寫密碼。
- 已加入會員註冊、登入、登出與資料隔離。第一次開啟請自行註冊（密碼至少 12 字元）；第一位會員會接收現有訓練、課表及自訂動作。尚無雲端同步、電子郵件驗證、忘記密碼或原生 iOS／Android。公開部署注意事項及 GitHub 排除清單見 [GITHUB-SAFETY.md](GITHUB-SAFETY.md)。
- 計時器依截止時間計算，切頁／重新整理後可恢復。瀏覽器關閉、手機鎖屏或系統暫停網頁時，音效通知不保證即時；再次開啟會校正剩餘秒數。
- 休息設定保存在瀏覽器，不會作為每一組的歷史實際休息秒數寫入資料庫；多分頁請使用一個分頁計時。
- 畫面沒有預填虛構訓練資料。字型使用 Google Fonts，無網路時回退至系統字型。
- 官方環境需求：[Spring Boot](https://docs.spring.io/spring-boot/3.5/system-requirements.html)、[Vite](https://vite.dev/guide/)。

## 突破紀錄、每週任務與回顧卡

- 儲存新訓練後開啟回顧卡；有既有基準且最高重量或同動作單次總量嚴格增加時，顯示突破慶祝動畫。平手、首次建立基準不算突破；修改既有訓練只有進一步提高紀錄才慶祝。比較排除該筆自身與較晚日期，同日紀錄彼此納入比較。尊重系統減少動畫設定。
- 總覽可設定每週 1–7 個訓練日，預設 3 天。目標保存於各會員資料庫欄位 `weekly_goal`；週一至週日以本機日期計算，相同日期只算一次。完成時顯示本週徽章，刪除紀錄會重新計算，並非永久成就收藏。
- 每笔紀錄的回顧卡按鈕可重新開啟圖片，下載 900×1050 PNG。暱稱預設隱藏，可隱藏重量；卡片不含電子郵件、筆記及訓練標題。最多列出六個動作，其餘顯示數量。圖片在瀏覽器本機產生，不會自動上傳社群。

## 肌群地圖與訓練日曆

- 總覽提供正面／背面肌群示意圖，紫色標記本週有儲存組數的主要肌群。支援點選、鍵盤與文字按鈕，查看本週組數及全部歷史中的最近訓練日期。自訂肌群以文字按鈕補充，不推估恢復狀態。
- 「訓練日曆」提供週一起始月曆、月份切換與每日紀錄。可將自己的既有課表安排至今天或未來日期；同課表同日不可重複安排。
- 安排儲存在會員隔離的 `scheduled_workouts` 表，不計入訓練統計。到日期後可帶入訓練表單並自行儲存，亦可補登過往安排。安排不自動判定完成，保留作為規劃紀錄；可取消安排而不影響實際訓練。
- 課表更新後安排使用最新內容，刪除課表會連帶移除其安排。API：GET/POST `/api/schedule`，DELETE `/api/schedule/{id}`。

## 超級組與 RPE

- 訓練或課表編輯器先新增兩組並選擇不同動作，點第一組下方「與下一組配對」。每輪由相鄰 A/B 組成，可「再加一輪 A/B」、解除配對或刪除組數。
- B 須等 A 完成後才能勾選；完成 A 會停止舊休息倒數並聚焦 B，兩組完成後依 B 動作的休息秒數啟動倒數。未配對的普通組維持完成即休息；取消完成不會另啟動計時。
- RPE 選填 1–10，以 0.5 為間隔，代表當次主觀費力程度。表單會尋找最近相同動作、重量及次數的 RPE（排除正在編輯與較晚日期），顯示較輕鬆／較吃力／相同；不是客觀強度或恢復判定。
- 訓練紀錄及 CSV 保留 RPE 與配對；舊資料兩欄為空。課表可保存參考 RPE，開始新訓練時清空實際 RPE，避免誤記；單一動作的歷史帶入會解除原配對並清空 RPE。
- H2 `workout_sets`、`template_sets` 新增可空的 `rpe` 與 `superset_id`，保留既有紀錄。每個配對 ID 必須恰好連結相鄰兩個不同動作。

## Google 登入

已加入可選的 Google OpenID Connect 登入與既有帳號安全連結。預設關閉；設定 `GOOGLE_LOGIN_ENABLED`、`GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`GOOGLE_REDIRECT_URI` 後重新啟動。完整建立用戶端、回呼網址與測試流程見 [GOOGLE-LOGIN.md](GOOGLE-LOGIN.md)。

Google 首次登入可建立會員；同信箱的舊帳號必須再次驗證原密碼才會連結。這不會改變原會員資料隔離或取代電子郵件登入。尚未用真實 Google 憑證完成授權驗證。
